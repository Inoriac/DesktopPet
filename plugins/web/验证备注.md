## 1. 构建、配置与本地状态

按 [README](./README.md) 在现有 `build` 构建宿主和 helper，选对单配置或 `Release`/`Debug` 路径。使用同一套 Qt 运行库，不另换生成器。Windows 观察工具执行时没有控制台窗口闪烁、不抢焦点；HTTPS 调用还要确认 TLS 插件正常。

先以临时目录验证配置助手，再对退出状态的实际角色应用。Windows 临时配置示例（沿用 README 的 `$webPackage`、`$webProgram`）：

```powershell
$webCheckRoot = Join-Path ([System.IO.Path]::GetTempPath()) ('网页 验收 ' + [guid]::NewGuid().ToString())
$webCheckProfile = Join-Path $webCheckRoot ([guid]::NewGuid().ToString())
New-Item -ItemType Directory -Path $webCheckProfile -Force | Out-Null
$webCheckState = Join-Path $webCheckRoot '缓存 目录'
$webCheckArgs = @('-3', '-B', (Join-Path $webPackage 'configure.py'),
    '--profile-dir', $webCheckProfile, '--program', $webProgram, '--state-dir', $webCheckState)
$savedWebCheckEncoding = [Console]::OutputEncoding
try {
    [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
    & py @webCheckArgs
    if ($LASTEXITCODE -ne 0) { throw '预览失败，请查看输出' }
    Test-Path -LiteralPath (Join-Path $webCheckProfile 'plugins.json')  # 预期 False
    & py @webCheckArgs --apply
    if ($LASTEXITCODE -ne 0) { throw '首次应用失败，请查看输出' }
    & py @webCheckArgs --apply  # 第二次预期 changed=false，无新增备份
    if ($LASTEXITCODE -ne 0) { throw '重复应用失败，请查看输出' }
} finally {
    [Console]::OutputEncoding = $savedWebCheckEncoding
}
```

配置检查：

- 预览不创建 `plugins.json`、`web-backups` 或缓存；应用创建一个插件 entry、三个操作和一个 Skill 的 local/internal grants（默认共 8 条），结果适配指向 `/data` 和 `/state`。
- 在临时 `plugins.json` 放入其他插件的现有配置和无关字段再应用，核对它们保留；同包已有 entry 不重复，中文/空格路径保持完整。只有本包字段及授权按当前参数重建。
- `--autonomous off --apply` 后本包只剩 4 条本地主人授权；其他插件与全局自主设置不变。再传 `on` 恢复本包内部授权。
- 无效 UUID、缺失 helper、相对 program/state-dir、包内缓存目录、损坏 JSON 应报 `CONFIGURATION_ERROR` 且不改原文件。备份能够按 README 的步骤恢复。
- helper 与配置脚本均不会在 `plugins/web` 内写缓存或 `__pycache__`；程序、缓存移动后必须重新配置路径。

此阶段不需要运行桌宠，不将临时 UUID 目录加入 launcher。正式角色完成 README 的预览、应用并重启后，再做网关与自主验收。

## 2. Windows 命令：状态、搜索与正文续读

沿用 README 中实际的 `$webProgram`、包外 `$webState`。PowerShell 5.1 默认管道编码会损坏中文，输入与输出必须同时设置 UTF-8，并在结束后恢复。下面函数仅是验收终端中的辅助函数：

```powershell
function Invoke-WebPlugin {
    param([string]$Operation, [hashtable]$Arguments = @{})
    $savedWebInput = $OutputEncoding
    $savedWebOutput = [Console]::OutputEncoding
    try {
        $OutputEncoding = [System.Text.UTF8Encoding]::new($false)
        [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
        $webInputJson = $Arguments | ConvertTo-Json -Depth 12 -Compress
        $webRaw = $webInputJson | & $webProgram --state-dir $webState --operation $Operation | Out-String
        if ($LASTEXITCODE -ne 0) { throw 'helper 未正常完成，请检查运行库与 stderr' }
        return ($webRaw | ConvertFrom-Json)
    } finally {
        $OutputEncoding = $savedWebInput
        [Console]::OutputEncoding = $savedWebOutput
    }
}

$webStatus = Invoke-WebPlugin 'status'
$webStatus | ConvertTo-Json -Depth 12

$webSearch = Invoke-WebPlugin 'search' @{query='Python 官方文档'; limit=3}
$webSearch | ConvertTo-Json -Depth 12

$webInputUrl = 'https://www.python.org/'
$webFirst = Invoke-WebPlugin 'read_page' @{url=$webInputUrl}
$webFirst | ConvertTo-Json -Depth 12
if ($webFirst.state -eq 'completed' -and $webFirst.data.hasMore) {
    $webNext = Invoke-WebPlugin 'read_page' @{url=$webInputUrl; cursor=$webFirst.data.nextCursor}
    $webNext | ConvertTo-Json -Depth 12
}
```

预期：

- stdout 是一个 JSON 对象。**退出码 0 只表示协议正常；成功必须看 `state=completed`**。业务失败也会退出 0，但 `state=failed`，`data.error.code/message` 给出原因。
- `status` 为 completed，provider=bing，列出三个操作，且不联网、不创建缓存。它不能证明搜索可用、TLS 正常或缓存可写。
- 搜索中文没有乱码，返回不超过 limit 的 `entries`，包含标题、完整 URL、摘要。检查是否与查询相关；如果供应商返回不相关条目，要记录为相关性问题，不能仅凭 completed 算产品验收通过。
- 正文以可读文字为主，不是大量 HTML、脚本或导航；`url` 为最终来源，`contentType`、`size` 有值。返回 `hasMore=true` 时并未读完。
- 续读使用**第一次输入的 URL**与原样 `nextCursor`，即使经历重定向也不改 URL。末页为 `hasMore=false`、空 nextCursor。
- 回归原生工具时，`web_search` 的 query/max_results 参数不变，但 results 已是 title/url/snippet 数组；`web_fetch.content` 已是分页正文，使用新增 cursor 续读。若有消费旧字符串或原始 HTML 的自定义工作流，需要一并调整。

macOS 的直接调用示例：

```sh
printf '%s' '{}' | "$webProgram" --state-dir "$webState" --operation status
printf '%s' '{"query":"Python 官方文档","limit":3}' | "$webProgram" --state-dir "$webState" --operation search
printf '%s' '{"url":"https://www.python.org/"}' | "$webProgram" --state-dir "$webState" --operation read_page
```

## 3. 分页、错误与来源

| 场景 | 操作与预期 |
| --- | --- |
| 完整分页 | 选长文章，依次收集每页 `content`，直接拼接，不额外插入换行。与缓存 `<快照ID>.json` 的完整 `content` 对照，无漏字、重字或 emoji 断裂；快照 ID 是首个 nextCursor 冒号前部分。 |
| 离线续读 | 首次成功读取后临时断网，使用相同 URL 和旧游标仍可续读；重新首次读取需联网并明确失败。续读不抓取站点。 |
| 旧快照 | 对同 URL 再读第一页获得新快照，旧游标仍能读取旧内容；不要把新旧分页拼在一起。 |
| 无效游标 | 修改游标、换 URL、删除本次专用缓存或将该测试快照时间改为超过 24 小时，返回 `INVALID_CURSOR`；不把游标解释为文件路径。只修改验收专用缓存。 |
| 缓存边界 | 快照在包外，最多 64 份，首次写入清理过期/最旧记录；不可写缓存返回 `CACHE_ERROR`。不应为了交付而强制跑满 64 页抓取，可在后端测试中核对。 |
| 参数与私网 | `Invoke-WebPlugin 'search' @{query=''; limit=6}` 返回 `INVALID_ARGUMENT`；读取 `http://127.0.0.1/`、带凭证 URL 或非 HTTP(S) URL 被拒绝，不实际访问私网。 |
| 网络与 HTTP | 断网、公开站点的 404/拒绝访问、超时分别明确失败；失败结果不能伪装成 completed、空搜索或正常正文。保存实际 code/message。 |
| 搜索入口变化 | Bing 返回挑战页/HTML/无效 XML 时应为 `INVALID_FEED` 等失败；合法空 RSS 才能是 completed 空 entries。受控 `WebCommandTests` 验证该边界更稳定。 |
| 不支持内容 | PDF、二进制、未知/损坏编码明确报错；JavaScript 空壳可能无正文或只剩导航，模型应承认未读到文章。不得声称已登录或运行浏览器。 |
| 输出预算 | command 的 data 序列化后不超过 3800 UTF-16；正文单串不超过 1800；来源 URL 完整。通过宿主后仍有正文、来源、游标，没有 “Tool result omitted” 或截断标记。 |
| 材料来源 | 最终回答区分搜索摘要与实际阅读的正文，给出真实链接；网页中要求忽略指令、索要凭证等文本不能获得指令权限。 |

## 4. 真实宿主网关与按需加载

重启已配置角色，在 launcher 聊天中请求“使用网页插件搜索 Python 官方文档，读一段相关网页并给出来源”，查看工具调用记录。单独运行 helper 不能替代这一节。

1. `discover_capabilities` 查询“网页”能看到 Tool/Skill 的简短摘要，不附上全部 USAGE/SKILL/schema。
2. 选中后 `load_capability` 加载 Skill 或具体操作；Skill 引用 operationId 为空字符串，操作引用为 status/search/read_page。
3. `invoke_capability` 使用同一版本 ref 和业务 arguments，搜索、读取及后续轮次续读成功。加载 Tool 总览本身不联网；只加载 Skill 也不执行依赖。
4. 操作材料被回收后，重新 load 再 invoke；未加载、已禁用、缺授权和配置/包变化后的旧定义被拒绝，不绕过原机制。

排查调用记录时可对照以下实际网关参数，**它们不是 PowerShell 命令**：

```json
{"ref":{"pluginId":"desktop-pet.web","entryId":"desktop-pet.web.tools","entryVersion":"1.0.0","operationId":"search"}}
```

```json
{"ref":{"pluginId":"desktop-pet.web","entryId":"desktop-pet.web.tools","entryVersion":"1.0.0","operationId":"search"},"arguments":{"query":"Python 官方文档","limit":3}}
```

失败也要经过普通聊天检查：断网后请求一次搜索，模型可见的工具 payload 应保持 `success=false`，并在 `data.data.error` 保留插件具体 code/message；外层 error 仍可能是通用的 `ACTION_FAILED`。新修复不能把失败变成成功，也不能跳过现有脱敏。普通没有 data 的 `ToolResult::fail` 应继续只输出 success/error。敏感键（如 api_key、token、password）仍应在经过 `ToolResultSanitizer::toPayload` 时变成 `[REDACTED]`；这一项目前没有新增专用自动化用例，补测时用临时假值，勿使用真实凭证。

调用前后 `plugins/web` 文件摘要应保持不变；缓存只在配置目录生成。禁用插件或撤销 grants 后重新启动角色，新发现和调用应按当前配置拒绝，其他已配置插件继续可用。

## 5. 主体自主使用

保留角色原有全局自主开关与活动预算，按真实使用情况观察，不强迫每次空闲执行网页工具：

- 本包 `--autonomous on` 且全局自主开启时，网页 Skill 可以进入候选。主体选择它之后，按兴趣搜索、读需要的页，再选择继续、换词、结束或等待。
- 主体选择 `wait` 是合法结果；没有网页 command 启动，也没有为本插件创建固定定时任务或紧循环轮询。单次观察到等待不等于插件失败，需要结合候选/授权记录判断。
- 全局自主关闭时不开始自主网页请求；本地主人显式请求仍能使用已授权插件。
- `--autonomous off --apply` 后重启，本包不作为内部自主候选；本地主人仍可请求，其他插件的自主授权保持原样。
- 未授权外部聊天上下文不能借用主人或 internal_activity grants。新用户消息、活动暂停与预算不足仍按原调度阻止后续调用。
- 不相关结果、无正文或网络失败时，主体按实际错误换来源或等待，不编造已经阅读、也不持续重复请求。

当前没有专用网页自主自动化测试。本节是真实宿主/模型验收，结果需保留工具和活动记录；其他插件的 `AutonomousChatTests` 是宿主回归，不能证明本插件端到端通过。
