# 使用 LX Music 听音乐

使用本技能前，加载 `desktop-pet.lx-music.tools` 的 `1.0.0` 版本。
本技能的方法只依赖该 Tool 的 12 个操作。所有调用都经过宿主的操作权限检查，
加载本技能不授予额外权限，也不要求用户绑定人物或聊天账号。

## 选择并播放音乐

1. 使用 `status` 查看真实播放状态。查询失败只说明 API 不可用，不会自动启动播放器。
2. 用户希望播放而 API 未开启时，使用显式的 `launch`；失败或 unknown 时如实说明，先读状态核对。
3. 想从已有歌单选音乐时，使用 `list_playlists` 取得真实歌单 ID，再用 `playlist_songs` 查看歌曲。
   注意空歌单和未知歌单不同；`truncated=true` 表示列表不完整。
4. 按实际请求选择 `search_play`（歌名、可选歌手）或 `play_playlist`（来自查询结果的歌单 ID）。
   自建歌单没有可用来源 ID 时无法用 Scheme 播放，不要伪造 URL 或宣称已播放。
5. 根据工具的实际完成边界报告结果。搜索播放会核对当前歌名与可选歌手；歌单播放只确认正在播放，
   不声称 API 已确认正在播放的是指定歌单。需要进一步核实时调用 `status`。

## 播放过程中

- `play` 继续播放，`pause` 暂停；只有观察到目标状态后才算 completed。
- `set_volume` 接收 0–100 的整数；不要把小数、字符串或越界值交给工具。
- `skip_next`、`skip_prev` 的 completed 仅表示 API 应答。需要知道当前曲目时再调用 `status`。
- `lyric` 读取当前歌曲歌词；没有真实歌词时不编造。

## 失败与不确定结果

`failed` 表示本次没有获得声明的成功结果，查看错误码和消息处理依赖或输入问题。
`unknown` 表示动作可能已经发生，必须先用 `status` 只读核对，禁止自动重发写操作。
尤其不能为“看看有没有切歌成功”再次切歌，也不能把歌名核对失败说成播放器没有收到指令。
搜索结果显示不同后缀、合作歌手或另一首歌时保留实际状态，让用户判断是否接受。

自主活动中只调用宿主明确授权的操作；没有写权限时可查看状态或歌单，不启动、不播放、不调音量。
本包没有收藏、取消收藏、任意跳转、改写歌单或下载功能，不按旧版说明尝试未声明的操作。
