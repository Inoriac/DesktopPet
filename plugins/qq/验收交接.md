## 命令层操作

以下实际网络命令仅由验收人员运行。命令 stdin 必须是一个 JSON 对象。先执行只读 status/list/read；测试发送只在准备好的测试会话进行。

macOS / Linux（替换绝对路径与号码）：

```sh
qq_python='/包外状态/venv/bin/python'
qq_settings='/包外状态/settings.json'
printf '%s\n' '{}' | "$qq_python" -B plugins/qq/adapter.py --settings "$qq_settings" --operation status
printf '%s\n' '{}' | "$qq_python" -B plugins/qq/adapter.py --settings "$qq_settings" --operation list
printf '%s\n' '{"chat_id":"group:123456789","limit":10}' | "$qq_python" -B plugins/qq/adapter.py --settings "$qq_settings" --operation read
printf '%s\n' '{"chat_id":"group:123456789","text":"QQ插件验收文本","reply_to":""}' | "$qq_python" -B plugins/qq/adapter.py --settings "$qq_settings" --operation send
printf '%s\n' '{"chat_id":"group:123456789","receipt_id":"填写刚才的receipt_id"}' | "$qq_python" -B plugins/qq/adapter.py --settings "$qq_settings" --operation receipt
```

Windows PowerShell（先使用 README 的 `$qqPython` 与 `$qqSettings`）：

```powershell
# Windows PowerShell 5 管道必须显式发 UTF-8，防止中文变为问号。
$OutputEncoding = New-Object System.Text.UTF8Encoding($false)
'{}' | & $qqPython -B plugins/qq/adapter.py --settings $qqSettings --operation status
'{}' | & $qqPython -B plugins/qq/adapter.py --settings $qqSettings --operation list
'{"chat_id":"group:123456789","limit":10}' | & $qqPython -B plugins/qq/adapter.py --settings $qqSettings --operation read
'{"chat_id":"group:123456789","text":"QQ插件验收文本","reply_to":""}' | & $qqPython -B plugins/qq/adapter.py --settings $qqSettings --operation send
'{"chat_id":"group:123456789","receipt_id":"填写刚才的receipt_id"}' | & $qqPython -B plugins/qq/adapter.py --settings $qqSettings --operation receipt
```

私聊将 chat_id 改为 `private:对方QQ号`。翻页时将 read 的 next_cursor 原样填入下一次 read 的 cursor。引用时填写同窗口已读消息的 message_id；不引用传空字符串。命令直调只能测适配器，不能证明宿主授权、上下文或发送归档已经正确，因此仍须下一节的宿主验收。

## 逐项验收

为每项记录通过/失败/不支持/未测与证据；不支持的平台扩展应记录限制，不能写成“完整历史通过”。

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| A1 | configure 不带 apply；再 apply 两次 | 预览无文件变化；只修改目标角色 plugins.json 并备份；第二次 changed=false；原插件设置保留 |
| A2 | status，然后临时改错 selfId 再 status，恢复配置 | 正常显示核对后的账号；错误账号 ACCOUNT_MISMATCH，无后续业务动作。换真正账号必须新 stateDir/connectionKey |
| A3 | 错 token、停止后端各运行一次 status/read | 明确失败、有限时间内结束；输出不包含 token 或含认证的 URL。恢复后端后可再试 |
| A4 | list、G/P read；G/P 互发中文、emoji、引用再 read | list 只有白名单；私聊/群聊正确分流，正文/说话者/引用正确；最近页最多 limit 条 |
| A5 | 有足够本地消息时连续读 next_cursor | 向更早页推进，不重复第一页；不同窗口游标不能混用；不推进 source ACK |
| A6 | 在后端不支持历史 API 的环境 read | completed + freshness=local_only + warning，仅展示已有本地日志。若后端无法模拟此条件，标记未测 |
| A7 | 向 G/P 发送一条普通文本和一条引用；查看实际客户端与回执 | 每次只出现一条；完成回执有实际 remote ID、正文、原始时间；引用指向当前窗口已知消息 |
| A8 | 发送包含字面 `[CQ:at,qq=all]` 的文本 | 保持文字，不触发真实 @ 所有人。发送图片不在本版范围 |
| A9 | SnowLuma 群发送，查看 get_msg 回执证据 | 只有目标/发送者/ID/time/content 匹配且 message_seq 为正整数才完成；seq=0 或缺失保持 unknown |
| A10 | NapCat 私聊发送并检查后端是否省略 get_msg 目标 | 省略时用目标限定的私聊历史确认同一消息；不支持历史或找不到同 ID 时 unknown，不猜测成功 |
| A11 | 受控制造响应超时/确认不可用，保存 receipt_id，然后恢复并 receipt | 不自动重发。知道远端 ID 时可重新核对；没有 ID 时仍 unknown。无法在实网稳定制造的条件标记“本地假服务已覆盖，实机未测” |
| H1 | 启动已配置角色，查看发现与按需加载 | 初始仅简短摘要；加载后见五项操作/Skill 方法；仅发现/加载不发任何消息 |
| H2 | 本地主人让主体查看 G/P；在 G 的外部活动尝试读取 P、列其他群或发送到 P | 本地可读；外部仅允许自己窗口 read/send/receipt，跨窗与外部 list 被宿主拒绝；本地直接 send 不获授权 |
| H3 | source on + autonomous off，并关闭宿主自主总开关；G/P 发送新消息 | 消息仍进入观察归档，身份稳定；没有自主工具执行或插件自行回复 |
| H4 | 开启所需自主授权和宿主自主活动；G/P 发新消息 | 既有宿主可产生该外部会话机会；主体可以等待、阅读或回应，不要求每条必回。回复进入对应窗口并归档实际回执 |
| H5 | 内部空闲活动决定去看看 QQ | 可 list/read 与等待/结束；本版不支持从内部任意选人主动开聊，不出现伪造 scope 或自动切换工具 |
| H6 | 实时消息归档后再 read，然后停开 source、重启角色 | 同条消息不重复入库；已确认游标稳定继续；同名不同 QQ 号不合并，QQ 用户不会自动成为 owner |
| H7 | source off 后发送消息，再手动 read | source 不监听；read 可查询近期历史。历史导入标 historical，不冒充新消息触发回复 |
| H8 | source on 时断开/恢复后端，期间发测试消息 | source 退避后重连，stop 能结束。记录实际补齐范围；后端历史有限，不能保证断线消息全恢复 |
| H9 | 收到图片/语音/视频/表情，以及临时私聊带 group_id | 媒体是诚实占位，无“看懂图片”声称；message_type=private 的消息仍进私聊，不误归群聊 |
| H10 | send unknown 后 receipt 确认完成，再 read/source | receipt 查询结果变化不改写宿主原 unknown 派发记录；新事实由 read/source 去重归档；没有第二次 send |
| H11 | 禁用 QQ 插件，尝试新调用；停止角色后恢复备份 | 新调用被拒绝，监听停止；原消息日志保留。恢复配置只影响该角色，其他功能继续可用 |

宿主验证以实际工具调用、观察档案和派发状态为证据，不以模型一句“我发好了”判定成功。source 与自主总开关是两回事；“收到消息但没回”也可能是主体正常选择等待，应结合活动与调用日志判断。
