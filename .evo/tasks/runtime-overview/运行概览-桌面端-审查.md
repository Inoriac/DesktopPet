# 运行概览实现审查

## 改造前发现

- 统计写到全局 log/statistics.json、按显示名称聚合，角色改名及多角色/多进程运行可能串数或覆盖。改为 profile UUID 独立文件，同角色重复实例以单写者锁避免覆盖。
- LlmChatService 仅统计重试最后一次，AIBrain 的后台模型用途缺独立维度；不能把一次聊天等同一次模型请求。统一按实际客户端尝试采集元数据，并关闭被路由包装的低层重复统计。
- Anthropic 原 promptTokens/totalTokens 没计入缓存输入，且取消/协议中断会丢失已报告 usage。需要保留使用量并统一完整输入口径。
- 缺 usage 与返回 0 原先无法区分，展示累计数字会造成零消耗假象。增加 reported 标记与未知用量计数。
- 情绪和自主活动已有真实状态，但 launcher 没有独立入口；直接轮询聊天快照会重复传消息。新建同管道只读运行查询。
- 原 AI 详细日志共享全局路径且无限增长；保留既有排障用途，增加 profile 隔离和轮转。新统计记录只包含元数据。

## 审查方法

按每个实现阶段检查数据来源、统计单次语义、角色归属、持久化恢复、旧数据兼容、只读查询、UI 状态切换与相关回归。每阶段实际发现、修复及测试结果在完成后追加，不把设计描述当作已经验证。

- 审查 StatisticManager 的兼容接口、UUID 归属、单写者锁、旧累计导入、检查点恢复、保存失败和历史上限；未发现阻断问题。坏文件保留，改名不改变存储身份，session 不从保存快照恢复。
- 审查 ModelRouter 实际派发、完成 gate、观察器生命周期、预算拒绝及服务直调重试；路由统计与低层统计互斥，失败 fallback 和结构修复分别计数。
- 补充修复 OpenAI observer 内取消时丢失已解析 usage，以及 Anthropic 取消/协议中断丢失 usage；只保留 ID/model/usage，不传播半截正文。
- RED 证据包含旧重试计数 1 而预期 2、Anthropic 输入 7 而预期 12，以及取消后的用量丢失；新增 API 测试首次因接口缺失编译失败。
- 构建并运行 StatisticManagerTests、ModelRouterTests、LlmTests、AnthropicMessagesClientTests：4/4 通过，QtTest 输出合计 127 passed、0 failed、0 skipped（含初始化/清理条目）。`git diff --check` 通过。

## Task 2 审查与验证

- 运行查询位于现有 authorize/consumeRequestBudget 之后，服务器覆盖 profileId，不读取消息、不改 revision。真实本地 socket 测试验证鉴权、伪造令牌、缺回调和查询不影响聊天状态。
- PetWindow 读取已有服务；纯序列化函数只输出八个自主状态键、任务状态及情绪数值，不输出任务目标、情绪来源事件或正文。情绪关闭/不可用无伪造状态。
- 详细日志路径由可信 runtimeDatabasePath 推导，继续交给 ChatSideEffectQueue；旧聊天 statistics 来源保留。日志轮转默认 8 MiB + 3 份备份，单条超限省略，失败返回 false；响应日志带 usage_reported。
- 新接口测试先因接口缺失 RED；LauncherChatServerTests、RuntimeOverviewTests、AiCallLoggerTests、ChatSideEffectQueueTests 构建后 4/4 GREEN。补充 usage_reported 断言经 RED→GREEN，修改后 AiCallLoggerTests 再次通过。
- 主程序 petwindow.cpp 与 ai_brain.cpp 对象单独编译通过，`git diff --check` 通过。Wave 核查：单个实现无冲突；设计场景有对应回归；新测试位于 tests/，CMake 已注册；§3.2.5 锚点和 context 留痕一致。
