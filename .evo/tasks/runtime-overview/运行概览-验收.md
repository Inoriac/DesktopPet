# 运行概览验收

日期：2026-10-20。本文是跨平台验收步骤；真实模型、Windows 实机结果由接手人员填写，本地合成检查不能替代实机结果。

## 环境记录

记录仓库提交、系统/架构、Qt 与 Python 版本、显示缩放比例、角色 UUID，以及模型 provider/model 和用途配置。报告不附 API key、完整 prompt、私人日记或未脱敏聊天日志。

## 界面与状态

1. 重建 C++ 核心并打开 launcher，导航进入“运行概览”。检查浅/深色、约 1000/700 像素窗口及 Windows 100%/150% 缩放，卡片、表格和数字不重叠；窄表格允许滚动。
2. 未启动角色时查看已保存统计或正常空态。不能显示实时心情、活动或假在线状态。“本次运行”不应冒充上一次启动。
3. 启动角色，检查 AI 开关、运行时长、排队数、自主状态、任务状态和情绪。触摸角色后查看互动计数和实际情绪变化；关闭情绪系统后，界面显示已关闭。
4. 自主开关关闭或暂停时显示对应状态。任务/后台整理/睡眠只有在实际发生时显示，打开概览本身不触发模型请求或自主动作。
5. 切到其他页面再返回，概览自动刷新；聊天发送、图片、历史搜索和停止回复仍正常，不因概览刷新卡顿或报聊天错误。
6. 退出核心或断开连接后，已有统计标记为非实时，心情/活动不可用；重新启动同角色恢复累计，本次运行重置。切换不同角色不显示上一个角色数据。

## 用量口径

1. 执行一条明确的聊天请求，对照模型响应 usage 与近期调用条目，再核对今天/本次运行/累计。一次用户输入可能包含多个模型用途或工具轮次，因此调用数不等于聊天条数。
2. 在已配置的环境触发视觉识别、后台整理等用途，确认用途/模型分组可区分，仍归属于同一角色。用途名称不是另一个聊天人物。
3. 对 OpenAI-compatible 响应检查输入、输出和总 token。对 Anthropic 检查完整输入等于 input_tokens + cache_read_input_tokens + cache_creation_input_tokens；缓存和推理子项已经包含在输入/输出中，不能再加到总量。
4. 服务未返回 usage 时，近期条目用量为未知、未知用量调用计数增加；不是消耗为零。显式返回全零 usage 则允许显示 0。统计是已报告用量之和，不代替供应商账单。
5. 受控的失败/fallback、结构修复和取消各有独立结果；每次真实客户端尝试只记一次。无法稳定在真实服务制造的错误，用本地假服务覆盖证据注明，不要反复发送真实请求凑异常。
6. 使用近期调用的用途、结果和模型筛选，跨页检查条目；最近记录保留 200 条、日趋势保留 90 天，累计不因近期条目移出而减少。趋势中的“今天”按本机日期计算。

## 兼容与日志

1. 使用测试角色验证改名后仍保留原 UUID 的累计。新角色用新目录，不能沿用另一个角色统计。
2. 首次升级且只注册一个角色、旧统计有精确名称匹配时，导入旧累计并显示迁入标记；旧数据没有时间/模型明细，不能伪造今天和模型分组。多角色不明确归属时保留旧文件。
3. 运行一段时间，等待一次保存再关闭/重启，累计时长不能重复增加上一会话；异常退出只保证最近一次保存检查点以前的数据。
4. 若重复启动同角色，后启动的统计应明确提示不能取得持久化锁，不覆盖正在运行实例的统计文件。
5. 打开日志目录可找到该角色模型详细日志；达到轮转上限后保留有限备份，超大单条日志注明省略。查看近期调用无需读取 prompt/回复正文；原全局旧日志保留。
6. 用独立临时角色模拟只读目录或损坏统计文件：界面提示读取/保存问题，核心聊天仍可用；损坏文件不自动覆盖。验收后恢复测试文件，不对个人真实数据做破坏性测试。
