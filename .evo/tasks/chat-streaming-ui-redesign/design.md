# 设计：桌宠流式聊天与 Fluent 界面重构

## 背景与目标

当前项目同时存在桌宠附近的液态玻璃输入/输出气泡，以及传统左右气泡式的独立聊天窗口。前者适合随手发起对话，但长回复依赖非流式结果和机械分页；后者更像即时通讯软件，没有体现用户与同一个桌宠长期维持一条连续对话的产品关系，也与 Python launcher 的 Fluent 视觉语言不一致。

本次设计保留“桌面快捷聊天 + 完整聊天窗口”两层结构，完成以下目标：

- 先建立支持 Anthropic Messages 的端到端真流式链路，再由新界面消费流式事件。
- 保留现有 OpenAI-compatible 能力，通过模型路由的 `provider` 选择客户端。
- 长回复在完整窗口中保持为一条连续消息，在桌宠气泡中按自然语义分段、自动播放并允许用户控制。
- 使用与 launcher 一致的 Fluent 设计语言重做一个可移动的小型聊天窗口，不引入 Python 运行时依赖。
- 每个 `profileId` 独立维护一条永久连续对话、阅读位置和窗口状态，不提供会话列表。
- 提供一个可编辑的 `DEFAULT` 默认连接，并允许文本、视觉、Daydream 等角色按需引用其他独立供应商连接；连接凭据与角色模型分离配置。

本次不引入 macOS Keychain 等新的凭据存储方案；API Key 延续现有行为，保存在本机 launcher 配置 JSON 中。语音合成延续“完整回复完成后播放”的现有语义，不在本次实现流式 TTS。

## 方案

### 1. 总体交互结构

聊天体验分为共享同一消息状态的两个展示层：

1. **桌面快捷层**：桌宠附近常驻一个弱化的紧凑输入条，悬停、聚焦或菜单操作后展开。桌宠回复使用轻量输出浮层，负责等待状态、短回复和长回复的分段播放。
2. **完整聊天层**：一个可移动、可调整尺寸的小窗口，展示该桌宠唯一的连续时间流。它负责完整历史、全文流式展示、阅读定位和稳定输入。

从任一入口发送的消息都进入同一轮回复。点击桌面回复浮层的“打开聊天”操作时，完整窗口定位到对应消息。关闭完整窗口不会结束对话，也不会影响桌面输入条。

### 2. 流式协议与客户端边界

新增 `AnthropicMessagesClient`，保留 `OpenAICompatibleClient`。模型路由根据 route 的 `provider` 选择协议适配器：

- `anthropic-messages` 使用 `POST /v1/messages` 和 Anthropic SSE。
- `openai-compatible` 保持现有非流式能力，并可在后续独立扩展其流式解析。
- Base URL 同时接受服务根地址、带 `/v1` 的地址和完整 `/v1/messages` 地址，客户端只做结构化规范化，不做字符串重复拼接。

Anthropic 客户端处理 `message_start`、`content_block_start`、`content_block_delta`、`content_block_stop`、`message_delta`、`message_stop`、`ping` 和 `error`。SSE 解析器必须支持网络半包、粘包、多行 data、CRLF/LF 和最后一个无空行事件。

协议层向上只发布规范化事件：请求开始、文本增量、展示状态变化、完整工具调用、完成和失败。`thinking_delta`、`signature_delta`、工具参数碎片和模型原始推理不会发布到 UI、聊天历史或日志正文。

### 3. 工具调用与回复状态机

一次用户请求在 UI 中始终对应同一条 assistant 消息，内部状态依次允许为：

`等待首字 -> 流式回复 -> 准备工具 -> 执行工具 -> 整理结果 -> 继续流式回复 -> 完成`

Anthropic 的 `tool_use` 参数通过 `input_json_delta` 累计，只在对应内容块结束、JSON 完整且参数校验通过后交给工具运行时。工具结果转换为 Anthropic 所需的 `user/tool_result` 内容块，再发起下一轮流式请求；下一轮文本继续追加到同一条 UI 消息中。

流式失败遵循可见性边界：首个文本增量出现前允许既有路由重试或 fallback；已经展示正文后不自动切换模型，以免重复或改写已显示内容，而是保留部分正文并标记“回复中断”，提供重试入口。停止生成同样保留已经收到的正文，并将消息记为已停止。

本地直接回复和直接工具路由也转换为相同的规范化事件，界面无需区分回复来源。

### 4. 动态等待状态

在首个可见正文到达前，桌面输出浮层和完整聊天消息使用阶段化的等待预设，而不是固定“思考中”：

- 等待模型：`组织语言中`、`翻找记忆中`、`脑袋转转中`。
- 查询或工具阶段：`找点线索中`、`出门打听中`、`忙活一下中`。
- 最终整理：`把线索串起来中`、`马上就好`。
- 轻松性格预设：`摸鱼中`、`假装很忙中`。

预设按当前阶段和桌宠表现风格选择，同一请求内避免重复，以约 2 秒的低频节奏轮换。首个正文增量到达时状态立即让位。状态文案只是交互反馈，不代表或泄露模型思维链；具体工具名、参数和原始工具输出默认不显示。

### 5. 长回复分段与播放

完整聊天窗口始终对一条 assistant 消息追加全文，不把长回复拆成多条聊天记录。

桌面输出浮层在流式文本后增加增量分段器：

- 优先以段落换行、句号、问号、感叹号和分号封段。
- 未出现自然边界时允许继续积累，到硬上限后选择最近的逗号或安全字符边界，避免截断 UTF-16 代理对和组合字符。
- 当前页仍在生成时稳定占据同一布局；封页后进入可播放队列，新增文本不会打断用户正在回看的旧页。
- 默认按文本长度计算阅读时长后自动进入下一页；鼠标悬停立即暂停，离开后延迟恢复。
- 提供上一页、下一页、暂停/继续和打开完整聊天窗口的图标控制；手动翻页后暂时停止自动抢页。
- 流式结束后保留最后一页至既有展示时长；存在未读后续页时不自动隐藏。

### 6. 完整聊天小窗口

C++ 窗口复刻 launcher 的设计语言而不依赖 `qfluentwidgets`：共享明暗主题键、字体层级、颜色、细边框、8px 以内圆角、输入控件状态、滚动条和图标语义。它不追求跨语言组件逐像素复制，但应被感知为同一产品。

窗口采用克制的单列时间流，不继续使用高饱和左右气泡：

- 用户消息右侧排列，使用轻量强调底色。
- 桌宠消息左侧排列，以可选择的正文块为主，减少大面积卡片背景。
- 系统状态居中、低强调展示，不混入角色消息样式。
- 顶栏显示当前桌宠身份和窗口操作；不加入会话列表或营销式说明区域。
- 底部输入框随内容在限定高度内自动增长，Enter 发送、Shift+Enter 换行；生成期间发送按钮切换为停止图标。
- 窗口几何位置和尺寸按 `profileId` 恢复，并保证恢复后仍位于当前可用屏幕范围。

### 7. 连续对话、历史与阅读分割线

每个 `profileId` 对应一条永久连续对话。历史文件迁移到应用数据目录下的 `profiles/<profileId>/`，消息增加稳定 ID、角色、时间、内容和完成状态。流式草稿在内存中更新，正常完成、失败或用户停止时持久化一次最终可见内容，避免为每个 token 写盘。

“上次看到这里”记录用户上次关闭或收起完整聊天窗口时，视口中确认读过的最后一条消息 ID。下次打开时在该消息之后插入单条阅读分割线，并定位到分割线附近；若没有新消息则不显示。日期变化和较长时间空档只使用普通时间标记，不创建新会话。

旧的全局 `log/chat_history.jsonl` 不能直接分配给多个身份。仅当注册表中只有一个有效桌宠身份时允许一次性导入；存在多个身份时保留旧文件但不自动混入任何新历史。

### 8. Launcher 配置入口与连接档案

配置继续使用 JSON，不引入 XML。新增 `modelEndpoints` 连接档案表，其中 `DEFAULT` 是始终存在且可编辑的默认连接，只保存 `provider`、Base URL、API Key、Anthropic 版本和额外请求头等连接信息，不保存模型名。`modelRoles.<role>.routes[*]` 通过 `endpointRef` 选择连接档案，并在 route 内独立保存模型名、能力和限制。这样用户通常只需配置一次 `DEFAULT`；视觉或 Daydream 使用其他平台时，再创建独立档案并替换对应 route 的 `endpointRef`。

launcher 的 AI 页面分成“连接档案”和“模型分工”：连接档案支持编辑、测试 `DEFAULT` 及其他命名连接；模型分工至少包含对话、视觉、快速提取、记忆巩固、日记和 Daydream，每项选择连接档案与模型。Daydream 默认引用 `DEFAULT`，但模型名独立，允许选择成本更低的模型，也允许改用具有独立 provider、Base URL 和 API Key 的档案。Anthropic 流式传输仍是客户端能力，不提供流式开关。

运行时先按 `endpointRef` 完整解析连接，再与 route 模型合成为 `LlmConfig`。任何被引用的档案缺少必填字段或引用不存在时，都直接判定该 route 无效；非 `DEFAULT` 档案尤其禁止逐字段回退到 `DEFAULT`，避免把默认 API Key 发给特殊供应商。日志、错误和连接测试只在当前档案边界内脱敏，不在角色间复制或回填 Key。

旧配置保持可读：没有 `modelEndpoints` 时，从 dialogue route、再从 profile 旧字段生成 `DEFAULT`；与默认连接相同的角色改为引用 `DEFAULT`，连接不同的角色保留为独立档案。旧 `daydream.model/maxTokens/temperature` 迁移到 `modelRoles.daydream.routes[0]`，原 `daydream` 对象继续只管理触发间隔、批量大小等行为参数。保存采用新 schema，同时保留未由 UI 管理的 fallback routes、limits 和未知平台字段。

Daydream 新增正式的 `ModelRole::Daydream`。`AIBrain::runNextDaydreamBatch` 与 `DaydreamSleepAdapter` 必须统一通过该角色解析配置，不再分别复制全局 `LlmConfig`、覆盖 `daydream.model` 或借用 `Consolidation`，从而保证两条执行路径使用同一供应商、凭据和模型。

### 9. 执行顺序

执行严格遵循“能力先行、界面后接入”：

1. 建立规范化流式事件契约、Anthropic 请求转换与 SSE 增量解析。
2. 接通 AIBrain 工具轮次、停止/失败/fallback 边界和单条回复状态机，并用最小测试验证协议链路。
3. 建立按 `profileId` 隔离的聊天历史、稳定消息 ID 和阅读位置。
4. 重构可移动的 Fluent 完整聊天窗口，使其消费同一流式状态。
5. 重构桌面输入条与输出浮层，接入自然分段、自动播放、悬停暂停和手动控制。
6. 扩展 launcher 的连接档案、各角色模型分工和连接测试，接入 Daydream 独立路由，完成迁移、明暗主题与异常状态验收。

### 10. 验证策略

当前开发环境为 macOS，仓库内 ONNX Runtime 无法在此完整运行，因此不以启动整个桌宠作为本次本机验收门槛。最小验证包括：

- Anthropic 请求体、system/message/tool_use/tool_result 转换测试。
- SSE 半包、粘包、多内容块、文本与工具参数交错、ping、error 和中断测试。
- 首字前 fallback、首字后中断、停止生成和工具续写状态机测试。
- 中文自然分段、硬上限、自动播放、悬停暂停和手动回看测试。
- `profileId` 历史隔离、单身份旧历史导入和上次阅读分割线测试。
- launcher `DEFAULT` 与特殊连接档案的保存恢复、旧配置迁移、缺失引用拒绝、跨角色 API Key 隔离和脱敏测试。
- Daydream 两条执行路径均解析 `ModelRole::Daydream`，并使用同一 endpoint/model 的最小路由测试。
- 运行 CMake 配置检查及不依赖 ONNX 的最小测试目标；完整桌宠、真实 Anthropic API 和视觉平台联调由填入实际地址、API Key 与模型后完成。

## 澄清结论

- [2026-08-27] 完整聊天采用可移动的小窗口，不采用屏幕侧边栏。
- [2026-08-27] 阅读分割线表示用户上次关闭或收起完整聊天窗口时看到的最后位置。
- [2026-08-27] 每个桌宠身份按 `profileId` 独立维护一条永久连续对话，不提供会话列表。
- [2026-08-27] 长回复采用自动播放、悬停暂停并支持手动翻页的桌面气泡体验。
- [2026-08-27] 先实现流式输出与工具调用解析，再重构聊天界面。
- [2026-08-27] 文本主接口使用 Anthropic Messages；保留既有 OpenAI-compatible 客户端。
- [2026-08-27] macOS 本地仅要求最小测试与 CMake 检查，不要求运行依赖现有 ONNX Runtime 的完整桌宠。
- [2026-08-28] 使用 `modelEndpoints` 连接档案与 `endpointRef`；`DEFAULT` 只共享 provider、Base URL、API Key 和协议参数，所有模型名始终由各 `modelRoles` 独立配置。
- [2026-08-28] Daydream 是独立模型角色，默认引用 `DEFAULT`，可选择轻量模型或切换到具有独立凭据的其他连接档案；两条 Daydream 执行路径必须使用同一角色路由。
