# Windows 连续交互报告修复

依据 `INTERACTION_VALIDATION_2026-10-18.md`（验收基线 `1a5ad3e`，报告提交 `25ff720`）。本轮在 macOS 使用临时数据库、合成消息和本地测试服务回归，不调用真实付费模型，不修改用户记忆或凭据。

## 1. 旧记忆归属隔离

- 多角色且无法确定旧记忆归属时，保留 Ambiguous 诊断，但使用当前角色的独立空库，正常启用角色运行时。不会复制、打开或归属迁移共享旧库。
- 迁移失败时不再返回旧库路径，启动过程在初始化存储之前返回 PROFILE_MIGRATION_FAILED；日志记录原因。
- 单角色迁移、已确认归属迁移和已有独立库继续使用原流程。
- ProfileDataMigratorTests 和 AgentRuntimeServicesTests 通过；新增回归先在旧实现失败。集成测试覆盖真实聊天副作用运行后旧库字节不变、新记忆进入独立库，以及损坏目标库不能回退到共享库。

Windows 复验：在临时目录准备旧库和两个角色，用新角色启动并发送一条记忆指令。确认新记录仅在 profiles/<当前角色>/memory.db，旧库无新增记忆、归属或迁移游标。原始旧库留待明确归属后单独导入，本次不自动重新归属已有数据。

## 2. 失败回复与重试

- 带原始消息关联的失败、中断、停止回复计入可见历史，即使没有生成正文也不会消失。JSONL、SQLite、最近窗口、历史分页和定位使用一致的边界；系统记录与无关联的空诊断仍进入调试面板。
- 聊天气泡显示“回复失败 / 回复中断 / 已停止回复”；失败和中断项提供持续可见的“重试”，复用原有文本与图片重试流程。中断时保留已收到的文字，原始技术错误仍只在调试信息中展示。
- 离线、AI 关闭、正在处理消息或提交草稿时禁用重试；正常用户发送失败仍保留草稿。
- ChatHistoryTests、ChatUiModelTests、AnthropicMessagesClientTests 通过；Python Launcher 聊天/图片/传输测试 63/63 通过。浅色、深色 460px 窄面板截图已检查，见 visual-qa；render_failure_qa.py 可复现合成状态。
- 新增本地 TCP 断连测试覆盖响应前关闭与流式正文中断，确认失败仅结束一次、后续请求可恢复。当前证据没有复现客户端永久失效，也无法确定 Windows 三次真实断连的根因；本次未添加盲目的自动重发。

Windows 复验：临时配置不可用端点触发一次回复失败，关闭提示后确认失败气泡仍在；重开 Launcher 和上滑历史仍可看到。恢复端点后点击重试（另覆盖图片消息），确认能收到新回复。真实断连若仍出现，应保留对应脱敏请求日志与服务端请求 ID，再核对服务端/代理和 Qt 传输情况。

## 3. 明确的长期记忆指令

- 补充识别“请长期记住”“补充一条请长期记住”“补充一下，请帮我记住”等句首指令，沿用现有 user_explicit / rule_v1 提取与写入策略。
- 报告原句现在直接写入 semantic 长期记忆；保留完整事实正文，重开数据库仍可读取，不必等待整理短期记忆。
- MemoryStrategyTests 通过。新增用例先复现原实现漏识别，再验证新写入及数据库重开；另覆盖引用他人话语、明确否定，不将其误判成记忆写入指令。原“记住：”兼容用例通过。

Windows 复验：用独立测试角色发送报告原句，检查 memory.db 中 semantic / user_explicit / rule_v1 条目，然后重启并询问盆栽名、位置和浇水时间。模型口头承诺本身仍不等于落库证据。
