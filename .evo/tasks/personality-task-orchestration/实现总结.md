# 性格演化与任务编排：实现与 Windows 验证

日期：2026-10-12。依据同目录《性格演化与任务编排-桌面端-初步设计.md》；原始讨论稿保留不改。

首版已接入 C++ 桌宠、SQLite 运行时与 Python launcher。本文区分自动化验证与尚未完成的真实服务商验收。

## 实现对应

| 设计范围 | 实现与行为 |
| --- | --- |
| 人格与关系 | 七维人格、四维关系；保留基线并记录长期偏移；关系按角色和用户隔离，限制单次和每日绝对变化。普通互动可增加熟悉度，闲置和拒绝本身不扣分。 |
| 人格证据 | 保存原始经历、来源类别、事实/感受/推测、场景、时间与消费版本；同维度至少 3 个独立来源、2 类场景、实际跨度 14 天，提交间隔至少 14 天。 |
| 原子版本 | 本地 preview 得到最终参数，再生成摘要；参数、行为风格、自我叙事、证据消费及变更 outbox 在同一身份事务发布；expectedVersion 冲突后重新评估。 |
| 睡眠演化 | PersonalityConsolidationStage 固定已提交事件截止，先提取证据、再生成摘要，随后日记；用户任务取消未提交阶段，迟到模型结果不提交。Daydream 保持独立批次与并发行为。 |
| 任务编排 | 独立 TaskOrchestrator 执行受理、规划、工具、观察、验证、重规划；普通聊天和简单生活指令保留原链路。 |
| 主观受理 | AgencyDecisionService 输出接受、协商、延后、拒绝；安全检查点可继续、协商、暂停、停止，记录人格与情绪及原因。模型故障不伪装成主观拒绝。 |
| 工具与预算 | 本地硬白名单与现有工具策略共同约束；不提供终端、脚本、任意写入及通用桌面控制。网络、文件和音乐工具在线程中执行；短本地动作排队执行并检查取消令牌。 |
| 持久化与恢复 | SQLite 保存状态、预算、原人格快照、调用 ID 和结果。关闭应用保存暂停状态；重启待用户确认；已成功动作去重，结果不明的副作用需核对后继续。 |
| 统一经历 | TaskExperienceAdapter 从事务 outbox 幂等补齐一次事实事件与情景记忆，再异步保存加密感受。暂停不是终结经历；没有用户反馈时明确记为未知。 |
| 聊天 UI | 任务卡展示进度、继续、暂停、停止、增加预算与不明动作核对；控制指令携带任务 ID，拒绝过期任务操作。 |

关键入口：`core/ai/task/`、`core/ai/ai_brain_tasks.cpp`、`core/ai/identity/`、`core/ai/reflection/personality_consolidation_stage.*`、`core/ai/runtime/agent_runtime_personality.cpp`。

## 来源与私密材料

- 任务请求、继续和停止等派生交互带任务标记，由终结的 TaskExperienceRecorded 承载该任务的独立原始来源，避免一个任务被重复计为多份成长证据。
- 内心活动沿用原始事件引用；日记保存实际提供给生成请求的 originalSourceIds，本地持久化时覆盖模型自行声称的引用。无精确引用的旧日记仍可阅读，但不能凭日记篇数增加独立证据。
- 模型可在固定场景词表中理解同一原始经历的场景；本地校验场景与原始来源一致性、时间和去重。未消费的证据允许修订理解，保持原始来源与时间；已消费证据不能重复累计。
- 人格演化角色可读取相关完整日记与内心活动；普通对话、受理和任务的上下文接口支持显式选择的必要私密片段，不自动注入全部日记。所有者入口的内容不作为模型上下文权限。
- 私密正文继续使用现有加密库，普通事件、情景记忆与工具输出不复制感受正文。AI 设置和 README 说明相关内容会交给对应角色配置的模型服务商处理。
- 私密库不可用时，事实和反思待处理意图保留；不降级明文。公开经历仍可在符合睡眠条件时参与人格演化。

## 使用与配置

可输入 `/task 比较两种方案并查证关键差异` 明确进入任务；调研、多来源比较、行程和文档分析等常见请求也会按本地规则路由。需要补充条件时在任务卡输入后继续。

新增模型角色为 `agencyDecision`、`taskExecution`、`personalityEvolution`。缺省复用 dialogue 路由，显式禁用不会借回退绕过；launcher 支持分别配置服务商连接与模型并保存读回。

活动 profile 下的配置示例：

```json
"taskOrchestration": {
  "maxToolCalls": 12,
  "maxReplans": 2,
  "maxActiveMs": 300000,
  "modelTimeoutMs": 60000,
  "toolTimeoutMs": 30000
}
```

失败调用和自动重试计入预算；等待用户和停机时间不计入活跃时间。普通继续不重置消耗；“增加预算并继续”明确增加 12 次工具调用、2 次重规划和 5 分钟活跃时间。未结束任务保留原始人格版本，关系和情绪在检查点刷新。

任务 store、证据和版本结构采用兼容增量建表/加列。事实事件以任务 ID 幂等写入，冲突内容不会静默覆盖。经历反思可重试，模型请求不跨越 SQLite 长事务。

## Windows 构建

已使用本机 Qt 6.5.3、MinGW 11.2、Ninja 构建。独立输出目录为 `build/codex-personality`，不覆盖原有其他构建目录。PowerShell 命令：

```powershell
$env:PATH = 'E:\Qt\Tools\mingw1120_64\bin;E:\Qt\6.5.3\mingw_64\bin;' + $env:PATH
cmake -S . -B build/codex-personality -G Ninja `
  '-DCMAKE_MAKE_PROGRAM=E:/CLion 2025.2.1/bin/ninja/win/x64/ninja.exe' `
  -DCMAKE_CXX_COMPILER=E:/Qt/Tools/mingw1120_64/bin/g++.exe `
  -DCMAKE_PREFIX_PATH=E:/Qt/6.5.3/mingw_64 `
  -DCMAKE_BUILD_TYPE=Debug -DDESKTOP_PET_ENABLE_ONNX_RUNTIME=OFF
cmake --build build/codex-personality --target Desktop_Pet `
  task_orchestrator_tests identity_state_tests personality_consolidation_tests `
  task_experience_tests sleep_cycle_tests module_connectivity_tests model_router_tests `
  event_ledger_tests -j 8
```

桌宠输出：`build/codex-personality/Desktop_Pet.exe`。通过 launcher 试用此构建时可设置：

```powershell
$env:DESKTOP_PET_EXECUTABLE = (Resolve-Path 'build/codex-personality/Desktop_Pet.exe').Path
.\.venv\Scripts\python.exe launcher/main.py
```

## 验证边界

1. 本机未检测到 libsodium 与 QtKeychain，生产私密反思按既有能力开关关闭。私密流程使用测试密钥、测试加密实现与假模型完成仓库级验证；真实加密和 Windows 密钥链需要安装依赖后另行验收。
2. 未调用真实模型服务商，也未执行真实联网任务；模型受理质量、网页引用质量和实际任务完成率尚需配置 API 后验证。测试中的结构化模型响应不代表真实服务商表现。
3. 本次完成构建、离屏 UI 检查和相关自动化回归；未启动实际桌宠窗口完成手动全流程验收，未覆盖所有历史测试目标。ONNX Runtime 在本次构建中关闭。
4. 复杂请求路由首版采用本地规则，并提供 `/task` 显式入口；没有引入额外路由模型。执行工具的物理取消能力取决于既有工具实现，停止后禁止新派发并丢弃迟到结果，不明副作用仍需核对。
