# Task 3 聊天记录搜索与定位验收

日期：2026-10-18。前序基线：35d8fc0（Task 2）。范围：系分 §3.4。

## 实现锚点核实

已核实 `LauncherChatClient.search_history(query,before_message_id,limit,request_token)`、
`request_history(before_message_id,around_message_id,limit,request_token)`、
`operationFinished(action,data)` 与 `historyFailed(action,token,detail)`。
复用 ChatPage 的最近窗口、历史游标、可见消息过滤、锚点恢复和任务操作；未修改管道或存储契约。

## 功能与异常路径

- 工具栏“聊天记录”、Ctrl+F、Esc；快捷键仅对当前可见 ChatPage 及其子控件生效。
- 显式关键字搜索、每页 30 条、重复 ID 去重、围绕关键词的纯文本摘要、空态和加载更多。
- 点击结果按 ID 查询上下文，替换历史窗口，将命中居中并描边 4 秒；可继续上滑分页。
- 历史窗口与有缺口的最新快照保持分离；“回到最新”恢复最近 40 条和底部跟随。
- 搜索、定位、旧页分别关联 token；连续搜索、连续定位、返回最新、断线和切角色丢弃过期查询。
  新定位会取消旧页和在途的搜索翻页，保留已有搜索结果；新的关键词搜索取消旧定位。
- 搜索失败保留关键词；翻页失败保留已返回的结果；定位失败保留会话与结果，重试同一目标。
  技术错误只进入诊断，不变成聊天消息。
- 宽度不足 860 像素的 ChatPage 将搜索栏移至顶部，上限 240 像素高；宽页面右侧栏为 310 像素。
  任务按钮与输入区保留完整宽度。这是 §3.4 的响应式布局细节，无接口或存储设计偏差。

## RED → GREEN

先增加搜索、分页、定位、迟到结果、重试和快捷键测试；26 项聊天页测试的首轮运行中新增场景
因 `open_history_search` / `search_panel` 尚不存在失败，原 19 项仍通过。
随后实现 UI 并通过；又补充隐藏页快捷键、定位竞争、搜索切角色和关键词摘要回归场景。

主代理进一步复现 around/旧页响应与实时快照在同一事件轮次到达的滚动竞争：
新行尚未布局时重捕锚点，导致居中定位或旧页阅读位置丢失。先增加两条 RED，分别复现
2026/4222 像素偏移；修复为跨连续 render 保留未完成的锚点，用户主动滚动仍立即取消它。
另加“定位返回后立即按 End，再收到快照”的场景，验证用户操作优先。
