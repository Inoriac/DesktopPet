# 工具层准入契约

日期：2026-10-15。

状态：本文整理本次对话中已确认的准入原则，作为工具提供者与项目主体之间的共同标准。声明载体采用 JSON 清单＋Markdown 使用说明；具体声明格式见已确认的《能力包声明模板与填写规则》。内部实现另行制定，不能从已撤回的技术设计草稿中自动继承。

## 1. 目的与范围

任何工具只要满足这份标准，就应当能够通过公开契约接入项目，使主体知道它能做什么、如何调用，以及怎样理解结果，而无需了解工具的内部实现。

本次保留现有激活池、海马体和记忆存储设计。QQ 仅是可扩展能力的举例，不是本契约的专用模块或业务需求。

## 2. 准入单位：能力包

能力包由一份使用说明和一组相关的可调用操作组成，是注册与管理的基本单位。

能力包可以包含：

- 多个具体操作，例如读取、搜索、导出。
- 通用调用入口，例如由模型根据说明组织命令参数的 CLI 入口。
- 上述两种方式的组合。

契约不限制操作粒度。通用入口仍须明确可用命令范围、参数组织方式和结果含义，不能只提供一个没有使用约定的执行入口。

脚本、CLI 和 MCP 均可作为接入方式，不要求所有工具先包装为 MCP 服务。

## 3. 两层信息

| 层次 | 能力包必须提供的内容 | 用途 |
| --- | --- | --- |
| 注册信息 | 唯一标识、名称、版本、简短用途，以及完整定义的入口 | 启动时登记，使主体知道有哪些能力，模型能够发现和选择 |
| 完整定义 | 使用说明、操作列表、调用方式、参数与结果说明、必要的环境和配置 | 需要使用时加载，使模型和主体能够实际使用 |

使用说明可以自由编写，但调用入口与调用规则必须明确。2026-10-15 确认使用 JSON 清单承载结构化声明、Markdown 承载使用说明，并在后续对话中确认了声明模板；具体字段以格式附件为准。

## 4. 最低准入要求

### 4.1 能够被发现

提供稳定且可区分的身份信息、简短用途和完整定义入口。主体无需阅读全部操作说明，就能向模型展示包的用途并定位详细内容。

### 4.2 能够被理解

说明适用场景、操作流程、前置条件、限制及必要的使用示例。对于可能修改文件、发送内容或改变其他状态的操作，应说明其行为影响。

### 4.3 能够被调用

明确每项操作的名称、用途、实际执行入口和参数约定，包括必要参数及其含义。通用 CLI 入口同样需要说明如何组织命令与参数。

只提供说明而没有可执行操作入口，或只提供脚本而没有调用规则，均不满足此项要求。

### 4.4 结果能够被判断

明确操作返回什么，以及成功、失败和仅受理分别表示什么。

如果操作只负责提交请求，结果必须能够与实际业务完成区分。失败时应提供足以理解失败原因的信息，不能让主体通过猜测判断结果。

### 4.5 运行条件明确

说明所需依赖、配置、登录或授权条件，以及使用者如何满足这些条件。工具当前能否运行，与其声明是否符合准入标准分开判断。

此项要求明确条件，不强制所有能力包提供同一种自动探测或安装机制。

### 4.6 不依赖主体内部实现

工具的业务逻辑不直接依赖项目内部类、数据库表或窗口对象。需要主体提供的能力时，通过公开契约交互。

主体和工具提供者依赖共同约定，而不是互相了解内部代码。接入一个符合既有公开契约的业务工具，不应要求修改主体的业务逻辑。

## 5. 主体的责任

作为契约的另一方，主体应当：

1. 启动时登记符合标准的能力包，使模型能够发现它们。
2. 需要使用时加载完整说明与操作定义。
3. 按声明的方式、参数及前置条件调用，不要求工具作者针对不同任务修改主体代码。
4. 如实保留结果含义，不把“已经受理”解释成“已经完成”。
5. 区分准入情况与当前可用性，能够说明缺少依赖、配置、登录或授权等原因。

## 6. 准入合格与当前可用分开判断

准入检查关注：契约信息是否完整、明确且可遵循。

运行检查关注：当前环境和条件是否足以执行。

| 情况 | 判断 |
| --- | --- |
| 声明完整、调用明确，但尚未安装所需 CLI | 可以通过准入；当前缺少依赖 |
| MCP 服务暂时离线，或外部系统尚未登录 | 可以通过准入；当前不可用，应说明原因 |
| 脚本能运行，但缺少参数或结果说明 | 不满足准入标准，需补齐调用约定 |
| 只有功能介绍，没有实际操作入口 | 不满足准入标准，需提供操作实现及调用方式 |
| 提供通用 CLI 入口，命令范围、参数与结果含义明确 | 可以满足准入标准，不必逐项拆成细粒度工具 |

## 7. 准入核对清单

- 能否凭注册信息区分并发现这个能力包？
- 能否定位完整定义，并理解何时、如何使用？
- 能否依据声明准确调用操作，而无需阅读内部实现？
- 能否依据约定解释返回结果，区分成功、失败与受理？
- 是否说清运行所需条件，以及如何满足这些条件？
- 是否通过公开契约交互，而不依赖主体内部实现？

以上均满足，说明能力包符合最低准入标准；能否立即执行，再按当前运行条件判断。

后续对契约表达格式的细化及工具层解耦，应以本文为准入基线。本文不规定内部类、线程、缓存、数据库、执行调度或具体权限实现。
