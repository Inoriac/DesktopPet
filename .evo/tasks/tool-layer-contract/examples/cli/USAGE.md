# Git 通用入口示例

本示例用一个 `example.git/query` 操作提供两种查询，展示通用 CLI 参数入口，不要求把每条命令注册为独立操作。

## 准备

使用者配置 Git 程序与 repository 工作目录。模型只提供 argv，不能通过业务参数替换可执行程序或仓库路径。

## 操作范围

本示例只接受以下两种完整参数数组，参数 Schema 中也做了相同限定：

| 目的 | 参数 |
| --- | --- |
| 查询 Git 版本 | `{"argv":["--version"]}` |
| 查询简短状态 | `{"argv":["status","--short"]}` |

固定参数 `--no-pager` 和 `--no-optional-locks` 由声明提供。argv 中每个字符串是独立参数，不填写一整段 shell 命令。

上述范围是本示例自己的选择，不是所有通用 CLI 的准入上限。其他能力包可以声明更丰富的命令及参数范围，但其说明、参数定义、入口和行为影响必须一致。

## 结果与失败

版本命令正常输出版本文本，具体值取决于实际安装。status --short 返回 Git 的简短状态文本；退出码为 0 且输出为空时，本次查询未报告变更。

仓库不存在、不是 Git 仓库或程序执行失败时，按非零退出码和 stderr 说明错误，不把失败当作干净状态。两种查询均无仅受理阶段。

## 行为影响

本入口没有写入、提交、重置、清理等命令。实际程序仍受本机与仓库配置影响；作者换用其他程序或扩大命令范围时，需要同步修改 effects、Schema 和说明。
