# 项目代码审查与清理

日期：2026-10-18。基线：0c1da1f。用户授权连续审查、修复、清理，每完成一部分 commit。

## 审查原则

- 先核实调用关系与替代路径，再删旧实现。仍服务正常使用或已有数据迁移的兼容路径保留。
- 优先处理日常可遇到的退出/取消/网络失败/配置问题，不为假设场景增加一套框架或重试策略。
- 修复用针对性的行为测试验证；纯删除/整理复用已有测试，最后跑完整构建和回归。
- 不删除用户运行数据，不操作真实外部账号/播放器，不推送提交。

## 第一部分：移除弃用 MCP 原型

- 全仓调用检查确认 McpToolAdapter 只出现在自身与 CMake，实际执行入口已经是 CapabilityExecutor→McpClient。
- 删除该适配器及编译登记；移除 McpClient 未使用的原型工具注入、服务器名称、QObject 通知外壳。协议初始化、枚举、调用、超时与进程关闭仍走原实现。
- 校验：plugin_runtime_tests、lx_music_plugin_tests 构建通过；PluginRuntimeTests、LxMusicPluginTests 2/2 通过（11.02 秒）；删除项全仓源码引用检查与 git diff --check 通过。

- 配置比较直接使用发给 worker 的 payload，去掉另一份不完整的字段列表。参考音频文本、输出目录、保存音频等设置改变会重新配置；仅切换朗读来源仍由宿主处理。
- 新增受控 Python 协议进程测试，覆盖关闭/队列丢弃/重启、异常退出与残缺输出、配置更新、错误解释器路径后恢复，不下载模型或使用音频设备。

## 第四部分：模型回调取消与资源释放

- 复现 OpenAI 兼容请求在 StageChanged 回调中取消后，继续调用已被清空的 observer，抛出 bad_function_call 并 SIGABRT。发布每个事件前核对终结状态，并保留当前回调直到调用结束；取消后不再产生正文。
- OpenAI 与 Anthropic 的 reply 清理安排到完成回调之前，避免完成回调释放客户端后再访问已销毁的 reply。删除 Anthropic 请求状态没有使用的 enable_shared_from_this 继承。
- 补充两种协议的回调内取消，以及成功/失败完成回调释放客户端，共 6 个行为用例。修复前定向复现 SIGABRT，修复后 AnthropicMessagesClientTests 全通过（1.96 秒），LlmTests 通过（0.61 秒）；构建及 diff 检查通过。
