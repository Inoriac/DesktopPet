# QQ 插件实现总结

交付日期：2026-10-20。实现计划的三个阶段已完成，真实 QQ 与 Windows 实机验收按用户要求留给接手人员。

## 交付内容

- 新增 `plugins/qq` 独立插件，通过 OneBot v11 正向 WebSocket 适配 NapCat / SnowLuma；借鉴 MaiBot 的协议与职责划分，使用原创实现，不复制其 GPL 源码。
- 提供 status/list/read/send/receipt、按需加载的 Skill，以及默认关闭的观察 source。主体通过现有自主活动决定阅读、等待或回应；插件不增加模型或自动回复循环。
- 复用现有观察、人物关系、授权和派发契约。私聊/群聊按会话键隔离，人物用 provider/connectionKey/QQ号识别，不把外部账号自动绑定为主人。
- 包外 SQLite 保存消息、重放水位和发送凭证；查询不推进监听 ACK。发送只派发一次，证据不完整保留 unknown，可用原凭证查询，不自动重发。
- 提供包外虚拟环境安装、单角色配置预览/备份/原子应用、依赖与来源说明，以及 Windows/macOS 操作和验收文档。

宿主业务代码、人物表和调度协议均未修改；包外变更仅涉及测试注册和文档索引。

既有套件中的真实音乐播放器与付费模型验收保持默认跳过，共 5 个 QtTest 用例；这些也不计作实机通过。

## 已修复的主要审查问题

- 登录验证前推送暂存、source 停止与重放、私聊消息路由和未知时间处理。
- OneBot async/畸形响应不能当作明确失败；发送后的歧义统一保留 unknown。
- NapCat 私聊确认缺目标时通过目标限定历史核对同一消息；明确错误目标不被覆盖，SnowLuma 群聊要求正整数 message_seq。
- read/list 超宿主输出预算时导致整页不可见：增加有界分页并通过真实 sanitizer 验证，保留归档原文。

## 当前边界与交接

内部活动可以自主浏览；发送必须处于对应外部会话活动。本版没有从内部活动任意选择联系人主动开聊的工具。

支持文本和回复引用；媒体仅保留诚实占位，尚不支持 QQ 图片理解或发送。近期历史每次最多拉取 50 条，不能保证补齐离线期间所有消息。单条长正文在模型输出中可能截短，本版没有正文内部翻页。

后续 receipt 确认只更新插件凭证，不回写宿主此前 unknown 派发账本；消息事实通过 read/source 归档。消息数据库目前不自动裁剪，部署者应管理包外状态目录。

实际后端兼容性、QQ 收发与 Windows 实机验证见 [验收交接](../../../plugins/qq/验收交接.md)；安装和配置见 [README](../../../plugins/qq/README.md)。NapCat 与 SnowLuma 应分别填写验收结果，不能将本地假服务通过替代平台验收。
