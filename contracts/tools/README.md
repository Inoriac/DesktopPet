# 插件系统指导与准入契约

本目录面向给予模型使用软件或运用技能的能力。Plugin 是安装、分发和管理单位，可以包含提供方法的 Skill、提供可执行操作的 Tool，或两者都有；模型根据各条目的简短描述选择并按需加载。

开发请先阅读 [插件系统开发指导](./插件系统开发指导.md)。主体与插件的后续实施以[自主 Agent 设计](../agent/自主Agent-身份记忆与活动运行时-桌面端系分.md)为主入口，按人物与记忆归属、活动运行机制、外部实践的依赖顺序推进。Tool 声明采用 JSON 清单＋Markdown 使用说明，支持脚本、CLI 和 MCP。Plugin / Skill 目标格式在新设计 §4 中定义，对应 Schema 和加载器仍需实现；现有 Tool Schema 不能验证它们。

## 复现验证

从仓库根目录执行，依赖只安装到临时目录，不修改项目依赖：

```sh
contract_deps="$(mktemp -d)"
python3 -m pip install --target "$contract_deps" jsonschema==4.23.0
PYTHONPATH="$contract_deps" python3 contracts/tools/verify_contract.py
```

需要 Python 3 和 Git。脚本输出逐项 JSON 结果；所有检查符合预期时退出码为 0，反例未被拒绝、正例未通过或执行异常均使验证失败。2026-10-15 的结果为 **62/62**。

验证包括声明结构、示例中的简单引用、业务参数正反例、参考计数脚本、临时 Git 仓库以及已有歌单脚本的查询函数。歌单查询只读取验证脚本创建的临时 SQLite 数据。不会连接 MCP、启动 LX Music 或桌宠、读取实际用户数据库，也不证明项目已经支持能力包加载。

引用核对仅支持这些示例中的直接配置引用和顶层属性映射，不是通用准入检查器；调度参数组合用例是用于验证标准表达能力的精简样例，不代替 C++ 调度器测试。脚本与 CLI 测试按示例约定直接执行，也不构成宿主加载器实现。

## 版本管理边界

正式工具契约及验证附件在本目录维护，主体演进设计在 `contracts/agent/` 维护。`.evo/` 继续保存本地过程记录；已撤回的系分草稿不属于本契约。2026-10-15 的契约验证未改变记忆设计或实施工具解耦；2026-10-16 的自主 Agent 设计进一步定义人物记忆与活动运行时，相关实现状态见该文档 §7。
