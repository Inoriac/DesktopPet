# 现有工具契约适配验证

日期：2026-10-15。代码基线：`fc3c5a2`。依据：[准入契约](./工具层准入契约.md)、[声明模板](./能力包声明模板.md)、[检查规则](./准入检查规则与示例核对.md)。

范围修正：能力定位已明确为给予模型使用软件或运用技能的能力，并区分 Skill 与 Tool。下文 46 个内部工具的核对保留为现状证据，不要求它们全部外部化，也不以主体内部接口开放作为外部包准入的前置条件。最新分类和加载要求见 [分类及按需加载约定](./Skill与Tool分类及按需加载约定.md)。

## 1. 结论与验证范围

现有工具的业务参数、查询/修改影响以及大部分结果含义，可以用当前 Tool 契约表达。**现有内部工具并不等于已经交付的外部 Tool 能力包**：它们没有按契约交付清单和使用说明，绝大多数实际入口是进程内 C++ 对象，主体也未实现外部 Skill/Tool 注册、按需加载和声明式调用。

本次覆盖 `PetWindow` 中 **46 个静态注册入口**，包括两个受策略配置限制的文件/命令入口和八个依赖形象桥接可用的入口，不代表任何一次启动都会注册 46 个工具。任务执行器的 20 个名称分支是其中部分工具的另一条执行路径，不重复计数；另检查 MCP 适配器。

验证分为源码核对、声明正反例和临时数据执行。没有启动桌宠或外部服务，没有对实际记忆、调度、形象、通知、音乐播放进行操作。代码核对不能证明这些业务已通过运行验收。

## 5. 按外部能力定位修正问题归属

1. **主体内部能力开放。** 记忆、提醒和形象是否提供外部接口，可以单独讨论；不再列为外部 Skill/Tool 契约的前置事项，不要求把内部工具全部包装成 MCP。
2. **动态参数。** 有这种需要的 Tool 应说明当前参数或可选值从哪里取得；固定参数 Tool 不必增加动态查询。Skill 引用 Tool 时遵循当前公开定义。现有 MCP source 可引用服务定义，其他 Tool 可提供公开候选查询，不能让模型猜测。
3. **宿主 Schema 支持。** 标准约束的校验与兼容性报告属于主体履行 Tool 契约的责任。当前实现不足仍然需要后续解决，但不是要求每个包作者另造一套参数约定。
4. **Skill 与 Tool 分类及按需加载。** 二者分别提供身份、类型、简短描述与完整内容入口；加载 Skill 的方法和加载 Tool 的操作定义是不同事项。已有机器 Schema 只覆盖 Tool，不能把纯 Skill 送入该 Schema 后以缺少 operations 为由拒绝。

结论是：**已验证的格式可作为脚本/CLI/MCP Tool 的准入基线；Skill 的独立分类和加载原则见新附件，尚需细化其机器声明格式。** 本报告没有验证主体的实际加载行为，也不因内部工具尚未外部化而判定外部契约不成立。
