# 插件运行时接入

一个插件通过 `plugin.json` 交付。主体先发现条目摘要，选择后加载 Skill 正文或 Tool 操作定义，再经宿主配置执行。新增软件沿用这条路径，不需要在主体中增加软件名称判断。

Tool 继续使用[能力包声明格式 1](./能力包声明模板.md)。Plugin、Skill 分别使用 [plugin.schema.json](./plugin.schema.json)、[skill.schema.json](./skill.schema.json)。实施范围和验收状态见[自主 Agent 主设计](../agent/自主Agent-身份记忆与活动运行时-桌面端系分.md)与其实施计划。

## 作者交付

最小的纯 Tool 插件可以复用[文本计数示例](./examples/script/capability.json)，在它所在目录增加 `plugin.json`：

```json
{
  "formatVersion": "1",
  "id": "example.text-plugin",
  "name": "文本计数插件",
  "version": "1.0.0",
  "summary": "统计输入文本的 Unicode 码点数。",
  "entries": [
    {"kind": "tool", "id": "example.text", "definition": "capability.json"}
  ]
}
```

同时提供 `capability.json`、它引用的 `USAGE.md`，以及可实际执行的脚本。计数脚本的参考实现见[示例说明](./examples/script/USAGE.md)。清单不能只描述一项尚未实现的操作。

纯 Skill 的 entry 使用 `kind: "skill"`，指向 `skill.json`；其 instructions 指向方法正文，dependencies 列出所需 Tool 的精确版本和 operation。纯 Skill 不要求 operations。混合插件在同一 entries 中同时声明两类条目。

条目 ID 必须与被引用清单一致。清单、正文和业务 Schema 引用使用包内相对路径，解析符号链接后也必须位于包内。程序路径、账号连接和 secret 由宿主配置提供；模型不决定这些路径或连接。

编译型 command 可参考[通用网页插件](../../plugins/web/README.md)：清单和按需说明放在 `plugins/web`，宿主固定配置包外 `desktop_pet_web` 程序与快照目录，运行时不修改包内文件。该包提供 `status`、`search`、`read_page`，与原生网页工具共用后端。角色配置助手只合并一个角色的 `plugins.json`，默认授予本包 local_owner/internal_activity 使用权，不改变全局自主开关。接入后仍由现有主体选择活动或等待。

## 宿主配置

`PluginRuntime` 读取当前角色运行目录下的 `plugins.json`，宿主也可以通过 `setHostConfiguration` 提交配置。配置归当前角色管理，不是可以由 Skill 正文申请的权限。下面字段分工与 Tool 格式 1 分开：

| 字段 | 用途 |
| --- | --- |
| plugins | 安装根目录 rootPath 和启用状态 enabled |
| configuration | 按 Tool entryId 提供其声明的 setting 值 |
| connections | MCP 连接名对应的绝对程序路径及参数数组 |
| grants | 可使用能力的角色、会话、操作、effects、执行器及对象/路径范围 |
| resultAdapters | 按 `entryId/operationId` 解释业务值、状态、回执和后续跟踪方式 |
| replyBindings | 固定外部会话、发送操作、grant 及参数与真实消息回执的映射 |
| observationBindings | 绑定观察账号、自身身份、允许会话及可选 source 的执行配置 |
| observationAdapters | 将准确 CapabilityRef 的 completed 查询结果映射为消息事实 |

以下配置仅演示文本计数。将 `pet` 和绝对路径替换为实际角色 ID、插件目录、Python 可执行程序和脚本路径：

```json
{
  "plugins": [
    {"rootPath": "/absolute/path/text-plugin", "enabled": true}
  ],
  "configuration": {
    "example.text": {
      "python": "/absolute/path/python3",
      "scriptPath": "/absolute/path/text-plugin/count.py"
    }
  },
  "connections": {},
  "grants": [
    {
      "id": "local-text-count",
      "profileId": "pet",
      "pluginId": "example.text-plugin",
      "conversationId": "local_owner",
      "entryId": "example.text",
      "operationId": "count",
      "effects": ["read"],
      "executor": "/absolute/path/python3",
      "autonomous": false
    }
  ],
  "resultAdapters": {
    "example.text/count": {"dataPointer": ""}
  }
}
```

grant 精确绑定 pluginId、entryId 和 operationId，条目换到其他插件不能沿用原授权。`local_owner` 授权限定本地主人上下文。外部会话使用宿主生成的稳定 conversationId；远端聊天窗口 ID 不能直接代替它。autonomous 独立控制自主使用，安装或启用插件不自动打开自主活动。

内部自主活动使用明确的宿主范围 `scope: "internal_activity"`，例如：

```json
{
  "id": "internal-text-count",
  "profileId": "pet",
  "pluginId": "example.text-plugin",
  "scope": "internal_activity",
  "entryId": "example.text",
  "operationId": "count",
  "effects": ["read"],
  "executor": "/absolute/path/python3",
  "autonomous": true
}
```

该范围只能匹配没有会话的 Internal 活动，不得同时填 conversationId。它不授予主人身份，也不授予所有外部会话；对象参数、路径、effect、执行器和自主开关继续独立校验。旧配置省略 scope 时沿用 conversationId 的精确匹配；未知 scope 或冲突字段拒绝加载。主体可以先发现摘要再加载细节，实际调用仍核验当前包版本及授权。

主体的内部记忆授权独立放在 `aiSettings.autonomy.memoryAccess`，默认 `{"owner":false,"conversationIds":[]}`。需要让自主选择参考主人记忆时由宿主设置 owner=true；指定会话记忆使用该 profile 的稳定 conversationId（最多 32 个）。该配置不授予插件执行或外部发言权限，外部活动仍按原会话重新准备材料。

## 摘要查询与按需加载

`discover_capabilities` 保留无参数调用，同时支持以下可选参数。查询范围由宿主根据当前角色、会话及自主授权确定，模型不能通过查询扩大范围。

| 参数 | 约定 |
| --- | --- |
| query | 最多 200 字符，匹配条目的身份、名称及完整摘要；支持 Unicode 大小写折叠、分词和中文连续片段 |
| limit | 每页 1～16 条，默认 8 条 |
| cursor | 上一页的 nextCursor；保持同一 query 和上下文 |

返回 `entries`、`total`、`hasMore`、`nextCursor`。`total` 是当前范围内匹配条目的总数，空结果也是成功查询；无后续页时 nextCursor 为空字符串。结果按相关度排序，同分按稳定身份排序，空 query 可稳定浏览整个目录。示例：

```json
{"query":"音乐","limit":8}
```

需要更多结果时，将返回的 nextCursor 填入下一次调用的 cursor。目录、配置、启用状态或学习技能内容变化、运行时重建，以及 query 或上下文改变，都会使旧游标返回 `CAPABILITY_CURSOR_INVALID`；此时去掉 cursor 重新查询。重复刷新相同学习技能快照不会使游标失效。错误参数返回 `INVALID_INPUT`。

发现只返回条目摘要，名称显示最多 128 字符、摘要最多 384 字符，过长时带省略号；搜索仍使用完整文本，身份与版本不裁剪。按原字段构造加载引用：`pluginId` 对应 pluginId、`id` 对应 entryId、`version` 对应 entryVersion。Tool 总览给出操作列表，再使用 operationId 加载具体参数、effects 和 result。Plugin/Skill/Tool 格式仍为 1，无需修改旧插件清单或 command/MCP 执行方式。

每次模型请求只保留当前 Tool 的最近两个操作及最近一个 Skill，同一版本定义的公共说明去重。切换能力后，需要重新 load 已回收的操作；直接 invoke 会得到 `CAPABILITY_CONTEXT_REQUIRED`。单份定义在脱敏后完整传递，上限为 32 KiB UTF-8 JSON；超限返回 `CAPABILITY_METADATA_TOO_LARGE`，应精简插件说明，不能依赖截断后的 Schema。

普通聊天每次回复最多进行 8 轮工具调用，可容纳发现、总览、操作加载和执行；长任务使用其独立的 Task 预算。

发现与加载保留完整执行记录和诊断日志，不新增生活记忆或工作记忆。持久任务步骤与真实业务结果不被请求投影覆盖；失败、accepted、unknown 和回执仍按原语义处理。

自主选择最多接收 16 条授权摘要：优先保留最多 8 条与当前活动线索相关的能力，其余位置从剩余条目轮换补充。禁用条目不进入候选。轮转只保存在当前主体内存，不代表安装后必然会选择或执行该插件；自主总开关、记忆授权及实际调用授权继续独立生效。

在 12 次合成加载的相同输入上，聊天消息数组由 36,843 降为 8,455 UTF-8 字节，Task steps 由 35,235 降为 7,114 字节；公共说明出现次数由 12 次降为 1 次。这里测量的是序列化字节数，未调用真实模型测量 token 或费用。

## 对象与路径范围

对固定对象的操作，可以在 grant 中使用 objectArguments，将 JSON Pointer 对应到允许的实际参数值；pathArguments 列出需要限制的路径参数 Pointer，allowedRootPaths 给出允许根目录。执行前检查实际参数与符号链接解析后的路径。示例：

```json
{
  "objectArguments": {"/conversation_id": "approved-remote-chat"},
  "pathArguments": ["/output_path"],
  "allowedRootPaths": ["/absolute/path/approved-output"]
}
```

这段是 grant 的可选字段示例，并不属于上述文本计数操作。配置要与实际操作参数匹配。

## 结果解释

command 使用程序路径和参数数组启动，按声明提供 JSON stdin；不将业务输入拼接成 shell 命令。JSON stdout 必须是一个完整 JSON 值，可以是对象、数组或标量。MCP 完成初始化、工具枚举和调用，保留完整 structuredContent/content；不会默认将第一段文本当作 JSON 业务结果。

resultAdapters 使用 JSON Pointer。空字符串表示完整结果，`/data` 表示对象的 data 字段。Tool 的 result.schema 校验选定的业务值：

| 配置 | 含义 |
| --- | --- |
| dataPointer | 业务结果的位置 |
| statePointer、stateMap | completion=reported 时，将实际状态值映射为 completed、accepted、failed 或 unknown |
| receiptPointer、trackingPointer | accepted 所需的实际回执及后续跟踪方式 |
| errorPointer | 可选业务错误的位置；不能覆盖进程失败或 MCP isError |

例如操作返回 `{"status":"queued","job_id":"j1","tracking":{"operation":"query_job","id":"j1"}}` 时，宿主可以按该操作的真实约定绑定：

```json
{
  "dataPointer": "",
  "statePointer": "/status",
  "stateMap": {"queued": "accepted", "done": "completed", "failed": "failed"},
  "receiptPointer": "/job_id",
  "trackingPointer": "/tracking"
}
```

后续查询操作或事件来源必须实际可用。accepted 表示已受理，不表示已完成；未知状态、断连或无法核实的写操作进入结果核对，不能自动重发。发消息的完成还需要真实远端消息回执，模型生成了回复正文不足以证明发送成功。

网页 command 的业务结果为 `{"state":"completed|failed","data":{...}}`，适配器绑定 `/state` 和 `/data`；退出码 0 只说明协议输出正常。失败的具体原因在 `data.error.code/message`，不能把网络失败当作空搜索或正常正文。`status` 仅检查本地参数，不代表联网或搜索可用。

宿主 `ToolResult::toJson` 在失败时也保留已有非空 data，再由统一 `ToolResultSanitizer` 脱敏和限制输出长度。普通模型因此可看到 `data.data.error` 的插件详情，而外层 success 仍为 false、error 仍保留宿主错误。失败且 data 为空时沿用原 success/error 结构；权限、终态与调度语义不变。

## 会话回复绑定

宿主在 `replyBindings` 中将一个外部会话绑定到已经安装并授权的发送操作。以下是该数组的一项示例；能力引用、授权 ID、连接和目标必须替换为实际值，对应操作需存在并通过加载校验：

```json
{
  "channel": "example-chat",
  "connectionKey": "account-one",
  "remoteConversationId": "approved-remote-chat",
  "kind": "group",
  "selfIdentity": {"provider": "example-chat", "namespace": "account-one", "remoteActorId": "pet-account"},
  "ref": {"pluginId": "example.chat-plugin", "entryId": "example.chat", "entryVersion": "1.0.0", "operationId": "send"},
  "grantRef": "send-approved-chat",
  "argumentBindings": {
    "/text": "content",
    "/target/conversation_id": "remoteConversationId",
    "/reply_to": "replyToRemoteId"
  },
  "remoteMessageIdPointer": "/remote_message_id",
  "contentPointer": "/content",
  "occurredAtPointer": "/occurred_at"
}
```

参数映射的键是非空 JSON Pointer，支持嵌套对象；值限定为以上三种宿主来源。原消息引用已经过会话存储解析，使用远端 messageId。回执 Pointer 相对于 `CapabilityOutcome.data`，三项都必须取得实际返回值，时间必须为有效 ISO 8601 字符串。后端修改后的正文和实际发送时间按回执归档；缺字段、accepted 或 unknown 都不视为发送完成。

异步加载或排队期间取消回复，会阻止后续发送。已经取得派发权的调用继续归档真实回执，即使用户切换角色或原会话服务已释放，记录也只写入原角色库。主系统不因结果未知自动重发。

普通自主 Tool 发送同样沿用 replyBindings 与派发账本。已经由 ConversationService 准备的回复携带宿主内部引用，不重复准备或发送；接口没有原生引用回复参数时可省略 replyToRemoteId 映射。实际回执在公开结果脱敏前取得并归档，归档故障保留原结果补写，不重发外部消息。

## 消息查询与可选观察源

消息查询通过 observationAdapters 显式绑定实际结果，source 使用独立的 [agent-observation-1 声明](./source.schema.json)。两者共用人物识别与消息幂等路径；source 默认关闭，没有 sources 的插件仍可主动查询。

查询可能只覆盖某个会话，因此不会推进整个账号的监听重放游标；只有有序 source 流提交后才确认该游标。消息入库与是否启动自主活动分别控制。具体协议、故障恢复和等待约定见[观察源与聊天插件接入](./观察源与聊天插件接入.md)，可直接运行的配置与适配器见[受控聊天示例](./examples/controlled-chat/README.md)。

## 验证与变更

先验证清单结构，再验证依赖、配置、授权和真实调用。JSON Schema 使用离线 2020-12 验证；不支持的关键字和包外引用会明确报错。结构校验通过不等于软件、账号或后端已经连接。

内容、宿主配置或启用状态变化后，旧加载句柄失效，调用前重新检查。禁用阻止新派发，已开始的调用仍保存原角色和原调用的真实回执。卸载插件不删除主体认识的人、会话或已形成的经历。

仓库的 C++ 运行时测试使用临时插件、独立子进程和受控 MCP 服务。真实软件接入需要另行验证其后端、账号、读取范围和发送回执；测试服务通过不能替代真实 QQ 验收。

网页插件的最终测试按用户安排延后，已编译的 `WebCommandTests` 与尚需手工验证的配置、完整网关、自主使用和 Windows 部署步骤见[验证备注](../../plugins/web/验证备注.md)。目前没有本插件专用网关/自主自动化测试，不能用其他插件的通过结果代替。
