# 准入检查规则与示例核对

日期：2026-10-15。状态：基于已确认准入契约和声明模板的检查附件，供核对检查口径。

依据：[准入契约](./工具层准入契约.md)、[声明模板](./能力包声明模板.md)。本附件规定检查什么、如何解释结论，不设计注册器、执行器、数据库或审批流程。

## 1. 检查结论必须说明覆盖范围

一次检查分别报告以下内容，不能仅给出一个没有依据的“通过”：

| 检查维度 | 回答的问题 | 结论 |
| --- | --- | --- |
| 声明结构与引用 | 信息是否齐全，类型与引用是否自洽？ | 通过 / 不通过 / 待核对 |
| 说明与操作含义 | 根据说明能否正确使用和解释结果，是否相互矛盾？ | 通过 / 不通过 / 待核对 |
| 当前运行条件 | 当前是否具备所声明的依赖、配置、登录和接口？ | 已就绪 / 未就绪 / 未检查 |

前两项是对准入声明的判断；第三项独立表达可用性。未运行过工具的报告必须明确写出“未进行实现行为验证”，不能把声明检查说成实际接入成功。

若发现明确的声明缺失或矛盾，报告不通过。若暂时无法判定说明含义，记录待核对及缺少的依据；不能把“不知道”写成已经通过。缺少 CLI、服务离线等运行问题本身不使完整声明准入失败。

不要求使用者为每个检查项逐一签字，也不要求为了准入执行有副作用的业务操作。结构检查可由程序完成；说明核对可以结合作者文档、服务公开定义和参考实现进行。

## 2. 结构检查

采用 [capability.schema.json](./capability.schema.json) 校验格式 1。机器 Schema 依据 JSON Schema 2020-12，不另建参数类型系统。

| 编号 | 检查项 | 不通过的例子 |
| --- | --- | --- |
| S01 | JSON 能无歧义解析 | JSON 语法错误，或同一对象存在重复键 |
| S02 | 注册信息齐全、类型正确且非空 | 缺少 id；summary 只有空白；version 是数字 |
| S03 | 完整定义包含说明、条件、配置和非空操作列表 | instructions 缺失，或 operations 为空 |
| S04 | 操作具有参数、调用、结果和行为影响定义 | 只有 description，没有 invocation |
| S05 | 调用方式与参数来源、结果格式匹配 | command 使用 parameters.source=mcp，或 MCP 使用 command 的文本输出约定 |
| S06 | 参数映射表达唯一 | 同一参数项同时含 input 与 expand |
| S07 | reported 结果说明如何区分阶段 | completion=reported，却没有 stateDescription |
| S08 | 输入/输出 Schema 自身符合其声明的标准 | type 写成非标准类型；输入根没有声明 object |
| S09 | 通用入口具有命令范围说明 | expand 允许传入命令参数，但没有 commandScope |

S01 的重复键检查需要在 JSON 解析时执行，不能把已经覆盖过重复键的对象交给 Schema 后宣称无歧义。S09 中 expand 是可自动识别的一种情况；其他允许输入决定命令类别的入口也需要通过说明核对判断。

Schema 对参数来源及参数引用对象采取明确的互斥结构；其他对象可以携带附加描述字段。附加字段不会自动成为标准调用语义。如果一个包必须依赖未约定字段才能正确执行，就需要补齐公开契约，不能由主体猜测其含义。

未知 formatVersion 应报告“当前检查器不支持此格式”，不擅自当成格式 1 解析。标准有效但当前宿主不支持的业务 Schema 特性，属于表达兼容性问题；不得静默忽略约束，也不能伪称该标准 Schema 本身语法错误。

## 3. 引用和一致性检查

以下多数规则不能只靠通用 JSON Schema 完成，需要结合包文件和字段关联检查：

| 编号 | 检查项 | 结论依据 |
| --- | --- | --- |
| R01 | 包内操作 id、配置 key、运行条件 id 不重复 | 重复标识导致引用无法唯一解释 |
| R02 | instructions 是可解析的相对路径，确有对应说明 | 缺少说明文件属于声明不完整；文件读取故障需说明尚未核实 |
| R03 | 所有 setting 引用存在，且直接引用项声明为必需 | 引用 python，configuration 却只有 pythonPath，属于声明错误 |
| R04 | 设置用途符合绑定 | program 对应 executable；workingDirectory 对应 path；MCP connection 对应 mcp_connection |
| R05 | input/expand 引用能对应合法业务参数 | input 取字符串，expand 取字符串数组；不可引用根本没有的字段 |
| R06 | 包内 Schema 引用和外部定义来源明确 | 包内引用断裂需修正；未声明来源的远程引用不能靠网络猜测补齐 |
| R07 | 同一注册范围内包 id 唯一 | 两个不同包使用同一 id 时报告冲突，不凭扫描顺序认定某个包有效 |

复杂 Schema 可能使用组合条件或引用。无法通过简单 properties 查找证明映射合法，不等于映射一定错误：需要解析实际 Schema；未能判定时记录待核对。具体调用时仍需依据实际输入判定引用是否存在及类型是否匹配，不能用准入检查替代参数校验。

R04 校验参数数组中的 setting 时，值必须能够作为一个字符串参数表达；不得把 mcp_connection 这样的宿主连接引用直接当成命令参数。secret 类型只表示配置用途，不允许通过说明自行取得实际秘密。

注册范围中的身份冲突需要被解决，但不代表某个包单独检查时一定结构错误。报告应同时列出冲突来源，使使用者能够选定正确的包或修正标识。

## 4. 说明核对

非空文本和正确的 Markdown 标题不证明说明足够使用，需要核对实际内容：

| 编号 | 核对内容 | 需要改正的情况 |
| --- | --- | --- |
| M01 | 使用场景与操作相符 | 摘要声称能导出，包中却没有对应操作或通用入口支持 |
| M02 | 操作名、参数来源和调用示例一致 | 说明引用不存在的操作，或把安装配置当成模型参数 |
| M03 | 正常示例满足输入 Schema | 例子传字符串，声明却要求字符串数组 |
| M04 | 命令范围与参数表达一致 | 说明只允许查询，参数/实现实际约定却包含未说明的修改行为 |
| M05 | 成功、受理、失败含义清楚 | 请求只返回任务 ID，却声明业务已完成；空输出无法区分成功与失败 |
| M06 | effects 与操作真实约定一致 | 明确发送或修改的操作声明为 read；依赖条件影响效果却没有说明 |
| M07 | 运行条件及准备方法明确 | 依赖外部 CLI、脚本或服务，却没有说明它是什么、如何取得或配置 |
| M08 | 能凭公开定义接入 | 作者要求直接访问主体某个内部对象或数据库表，才能完成操作 |

对于 accepted，至少提供后续确认办法，例如另一个查询操作、公开状态入口或明确的外部确认方式；不强制每个能力包增加同一种轮询接口。对于 reported，需说明状态字段或明确标记及各状态含义。

对于 result.schema，应能从 result.description 明确知道校验的是哪部分业务返回值。特别是 MCP 返回多个内容部分时，若没有说明具体业务数据位置，不能仅因为附了一份 Schema 就认定结果已经定义清楚。

## 5. 运行条件与引用式 MCP 定义

以下情况独立记录为当前未就绪或未检查，不冒充声明格式错误：

- 程序或解释器未安装，实际脚本尚未配置。
- 必需配置未填写，尚未登录或尚未取得所需授权。
- MCP 连接尚未建立，服务临时离线。
- 当前宿主尚未实现相应调用方式或不支持声明使用的 Schema 特性。

parameters.source=mcp 是合法的引用式声明。准确声明了连接来源、工具名和用途，不要求为了注册而复制远端 Schema 或强制服务立即在线。未取得实际输入定义时必须报告“参数定义未核实”，不能让模型猜参数调用。

如果后来取得的服务定义证明工具不存在，或参数、结果、行为与包说明矛盾，则已有证据表明声明需要修正。服务离线与服务明确报告“没有这个工具”是两种不同事实。

准入不保证第三方实现永远符合文档。更换程序、切换服务或修改参数含义后，应重新核对相关声明和实际接口，不能保留旧结果而假定新实现等价。

## 6. 检查报告应提供的信息

报告至少包含：包 id 与版本、检查的文件/来源、覆盖的检查维度、每个问题的位置、依据和改正办法。不得输出真实秘密作为配置问题的说明。

示例：

| 对象 | 问题位置 | 结论与原因 | 改正办法 |
| --- | --- | --- | --- |
| 某 command 操作 | invocation.program.setting | 声明不通过：引用的 python 未在 configuration 定义 | 补齐设置声明，或改为已经声明的配置键 |
| 已声明的 Python 依赖 | 实际运行环境 | 当前未就绪：尚未配置可执行路径 | 配置已安装的解释器；无需因此重写参数说明 |
| 某 MCP 操作 | parameters.source | 声明来源明确，实际参数定义未核实 | 连接服务后读取该工具公开定义，再决定是否可调用 |

## 7. 本轮三个示例的核对范围

| 示例 | 声明结构与本地引用 | 说明核对 | 当前运行条件 / 实现行为 |
| --- | --- | --- | --- |
| example.text | JSON、参数 Schema、配置引用、说明路径和操作名称一致 | 参考脚本与说明均按 Python 字符串长度计数，成功和失败含义明确 | 已从参考代码生成临时脚本并验证正常/错误输入；未接入主体 |
| example.git | 通用入口的两组参数与 enum、expand、commandScope 一致 | 说明区分正常空输出与失败，标明本机配置可能影响实际行为 | 已在临时仓库验证 Git 查询；未通过主体加载此包 |
| example.notes | 合法引用式 MCP 声明，连接设置和工具名明确 | 明确为假设服务示例，需用实际服务核对公开定义 | 未连接任何 MCP 服务，实际参数和结果未核实 |

示例声明已核对自洽，脚本和 CLI 另做了有限的临时数据执行；这些结果不表示项目已经完成能力包加载与执行。
